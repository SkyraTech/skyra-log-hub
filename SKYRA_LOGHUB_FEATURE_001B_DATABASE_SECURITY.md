## Runtime role separation and threat model

Isolated `skyra_org_runtime` has independent credentials, no superuser/create-role/create-database/role-inheritance authority and owns neither database, public schema nor tables. Grant artifact explicitly checks those boundaries and absence of inherited roles. It grants only relevant SELECT, tenant UPDATE(name,updated_at), audit INSERT/SELECT and timestamp-only UPDATE on identities/memberships required by PostgreSQL SELECT FOR SHARE. It grants no changes to identity keys, statuses, membership scope or role assignments, and no DDL. Test-only marker SELECT is separately granted for target verification, not part of protected application privileges.

Real runtime tests reject audit UPDATE/DELETE/TRUNCATE, trigger disabling, CREATE TABLE, and tenant id/code/created_at/status updates. Role grants and credential storage were created only inside the separately initialized PostgreSQL 17.9 cluster. Generated secrets are in the restricted ignored provisioner directory, never source/configuration reports.

The database role is trusted server infrastructure spanning tenants; tenant authorization is enforced in the Admin domain on every operation, not claimed as per-end-user RLS. A compromised writer credential can append records; it cannot rewrite existing audit history under these grants. Superusers/table owners can alter protections and are outside the immutable-runtime threat model. Protected runtime provisioning/credential activation and current ACL validation remain separate approval prerequisites.

## Concurrency and audit integrity

Strong ETag combines tenant UUID with exact epoch microseconds from updated_at. No JS Date rounding is used as the concurrency comparison. Header parsing rejects missing/weak/wildcard/malformed values; organization-context mismatch and stale values return 409. The tenant row is locked to capture accurate before metadata, and the UPDATE independently contains id/version predicates. Updated_at monotonically advances by at least one microsecond. A switched active organization cannot accidentally reuse an ETag from a different organization.

TENANT_UPDATED is inserted in the same Prisma transaction as the conditional update, through the existing audit adapter with the transaction client. It records stored actor identity, before/after display name, request correlation, timestamp and SUCCESS. Deliberately failed audit insertion rolls back both name and version; failed/unauthorized/stale mutations do not create successful mutation events. Audit insertion failures are not swallowed.

FEATURE-001A-001 still rejects ordinary audit UPDATE/DELETE/TRUNCATE and restricts parent deletion/update that would erase or rewrite history. Runtime cannot disable the triggers. No status editing, tenant deletion or retention bypass was added. Non-active tenant updates are rejected; UI presents readonly settings.
