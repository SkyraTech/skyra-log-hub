## 1. Machine Credential Architecture

Ingestion machine credentials authenticate automated agents, log shippers (e.g. Vector, Fluent Bit), microservice SDKs (`@skyra/logger-node`, `@skyra/logger-nestjs`, `skyra_logger`), and edge proxies pushing telemetry into `apps/ingestion-gateway`.

### 1.1 Ingestion Gateway Backward Compatibility
The Ingestion Gateway (`apps/ingestion-gateway/src/auth/auth.service.ts`) validates credentials using SHA-256 verifiers:
```typescript
public hashToken(rawToken: string): string {
  return crypto.createHash('sha256').update(rawToken).digest('hex');
}
```
**Mandate:** The administrative backend must adhere strictly to this existing verifier standard. No changes to the hashing algorithm, token length, or gateway database schema are permitted.

## 2. Token Format & Cryptographic Generation

Machine tokens generated by the Administration Service use the following canonical anatomy:

```text
  Prefix       Entropy / Random Secret Material (256 bits)
┌───────────┐┌────────────────────────────────────────────────────────┐
 skyra_live_  7c9e6679f42540dea44b0e7fc1f90ae7e268a731b8ef09214d039...
└───────────┘└────────────────────────────────────────────────────────┘
  (11 chars)                       (64 hex chars)
```

1. **Prefix (`key_prefix`):** Fixed identifier `skyra_live_` followed by the first 8 characters of random hex (total 19 characters). This prefix is stored in the database and visible in lists and audit logs to allow administrators to identify credentials without compromising the secret.
2. **Raw Token Secret:** 32 bytes of cryptographically secure pseudorandom entropy generated via `crypto.randomBytes(32).toString('hex')`.
3. **Database Storage (`key_hash`):**
   - The raw token is hashed immediately upon generation: `SHA256(rawToken)`.
   - The hex digest (`64` characters) is persisted to `ingestion_credentials.key_hash`.
   - **The raw token is NEVER persisted to disk, database, or logs.**

---

## 3. The "Reveal Exactly Once" Principle

To guarantee credential security:
- The raw plaintext token is returned **exactly once** in the response body of `POST /admin/v1/projects/{projectId}/credentials` or the rotation endpoint.
- Once the HTTP response is serialized, the raw token is completely discarded from server memory.
- Subsequent `GET` requests (list or detail) return only safe metadata (`id`, `keyPrefix`, `description`, `allowedProjects`, `allowedEnvironments`, `rateLimitPerMin`, `createdAt`, `expiresAt`, `isRevoked`, `lastUsedAt`).
- All admin responses containing credential material include strict HTTP caching directives:
  ```http
  Cache-Control: no-store, no-cache, must-revalidate, private
  Pragma: no-cache
  ```

## 4. Credential Lifecycle State Machine

```text
               ┌───────────────────────┐
               │    GENERATE TOKEN     │
               └───────────┬───────────┘
                           │ Secret shown once to admin
                           ▼
               ┌───────────────────────┐
         ┌────>│        ACTIVE         │<────┐
         │     └───────────┬───────────┘     │
         │                 │                 │
         │          Rotate │                 │
         │                 ▼                 │
         │     ┌───────────────────────┐     │
         │     │     ACTIVE_ROTATING   │     │
         │     │  (Grace overlap: 7d)  │     │
         │     └───────────┬───────────┘     │
Overlap  │                 │ Overlap expires │
Extended │                 ▼                 │
         │     ┌───────────────────────┐     │
         └─────│      DECOMMISSIONED   │     │
               └───────────┬───────────┘     │
                           │                 │
             Admin Revokes │   Admin Revokes │
                           ▼                 │
               ┌───────────────────────┐     │
               │        REVOKED        │─────┘
               │   (Immediate reject)  │
               └───────────────────────┘
```

### 4.1 States Defined
- **`ACTIVE`:** Normal operational status. Gateway validates token and admits log events.
- **`ACTIVE_ROTATING`:** Credential is undergoing scheduled rotation. A new replacement credential has been issued, but this existing credential remains admitted during an administrative grace period (default 7 days) to allow zero-downtime fleet configuration rollout.
- **`DECOMMISSIONED`:** Grace period expired; credential rejected by gateway.
- **`REVOKED`:** Emergency invalidation (e.g., token compromised). Gateway rejects authentication with `401 Unauthorized` immediately upon database update.

## 5. Zero-Downtime Rotation Workflow

Rotating machine credentials across a fleet of thousands of microservices without dropping logs requires an overlapping grace window:

1. **Step 1 — Rotation Request:** Administrator calls `POST /admin/v1/projects/{projectId}/credentials/{credentialId}/rotate` with optional `gracePeriodDays` (default 7, max 30).
2. **Step 2 — Atomic Transaction:**
   - A new credential record (`Credential B`) is created with identical `allowedProjects`, `allowedEnvironments`, and `rateLimitPerMin`.
   - The existing credential (`Credential A`) has its `expiresAt` updated to `now() + gracePeriodDays` and `isRevoked` remains `false`.
   - A foreign key link `Credential B.rotatedFromId = Credential A.id` is established.
3. **Step 3 — Secret Return:** The API returns `Credential B`'s raw token exactly once.
4. **Step 4 — Fleet Update:** DevOps teams update shippers and deployment manifests with `Credential B`.
5. **Step 5 — Automatic Decommission:** When `now() > Credential A.expiresAt`, the Gateway automatically rejects `Credential A`. Alternatively, an administrator can call `/revoke` to terminate the grace window prematurely once deployment is confirmed.

---

## 6. Audit & Security Redaction Rules

Administrative logging for credentials enforces strict redaction:
- **Audit Records:** Record only `credentialId`, `keyPrefix` (e.g. `skyra_live_7c9e...`), `allowedProjects`, and `actorUserId`.
- **Log Scrubber:** Gateway and Admin logger interceptors inspect outgoing logs and redact any string matching `skyra_live_[a-f0-9]{64}` with `[REDACTED_INGESTION_TOKEN]`.
