## 1. Executive Vision & Architectural Style

Skyra LogHub is an enterprise-grade, high-throughput centralized logging, durability, and analytical observability platform. The system is designed to provide:
1. **Durable, Lossless Ingestion:** Crash-recoverable binary Write-Ahead Log (WAL) with hardware-enforced `fsync` barriers and immutable canonical JSONL segment archival (Phase 2).
2. **High-Performance Analytical Search:** Direct vectorized JSONL scanning and derived columnar Apache Parquet acceleration powered by an embedded DuckDB execution engine (Phase 3).
3. **Strict Multi-Tenant Security:** Server-enforced tenant and project boundaries, zero cross-tenant information leakage, and hardened execution sandboxes.
4. **Clean, Modular, Extensible Codebase:** Predictable, maintainable structure balancing enterprise rigor with idiomatic TypeScript/Node.js ergonomics.

### Architectural Paradigm
The platform adopts a pragmatic combination of:
- **Modular Monorepo:** Distinct application boundaries (`apps/`) and reusable packages (`packages/`) orchestrated via pnpm workspaces.
- **Clean Architecture & Hexagonal Ports/Adapters:** Decoupled business/application logic from framework (NestJS), database (Prisma/PostgreSQL), and analytical storage engines (DuckDB/Parquet).
- **Contract-First API Design:** Authoritative OpenAPI 3.1 and JSON Schema (Draft 2020-12) contracts driving compile-time types and runtime boundary validation.
- **Fail-Closed Security by Default:** Authorization enforced at the service gate; input sanitization and containment verified before filesystem or database operations.

## 3. Core Architectural Invariants

Every service, package, and module in Skyra LogHub must strictly adhere to the following non-negotiable invariants:

### Invariant 1: Separation of Ingestion Durability and Analytical Querying
- The Ingestion Gateway (`apps/ingestion-gateway`) is a single-active-writer service whose sole mission is validating, framing, committing to binary WAL via `fsync`, and rotating immutable JSONL segments.
- The Query Service (`apps/query-service`) is an independent read-only service that scans finalized archive segments. Analytical queries can never consume ingestion CPU/memory or block ingestion WAL durability.

### Invariant 2: Immutable Canonical JSONL is the Sole Source of Truth
- The raw JSONL archive segments on disk are authoritative and permanent.
- PostgreSQL stores only administrative metadata, deduplication receipts, and segment index manifests. PostgreSQL **never** stores raw log event bodies.
- Apache Parquet is a derived, reproducible columnar cache. Deleting or rebuilding Parquet files incurs zero data loss.

### Invariant 3: Single-Active-Writer Topology
- Only one gateway instance may hold write locks (`.journal.owner`) on a specific WAL and archive partition.
- Concurrent multi-process file writing to the same journal or segment is strictly prohibited and guarded via atomic POSIX `O_CREAT | O_EXCL` leases.

### Invariant 4: Server-Authoritative Scoping
- A client-provided `tenant_id` or `project_id` in an HTTP request body is treated as a request filter, **never** as an authorization grant.
- Authorization scope is derived exclusively from the authenticated cryptographic token (Bearer token or JWT principal).
- Cross-tenant data retrieval is prevented at the database and filesystem resolution boundaries.

### Invariant 5: Safe Filesystem Containment
- The application never passes raw user-supplied strings into filesystem operations (`fs.open`, `path.join`, DuckDB table functions).
- All scanned files are discovered via verified PostgreSQL catalog records, resolved against `ARCHIVE_ROOT`, and verified against symlink escapes via `fs.realpathSync`.
